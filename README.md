## 🚀 About This Book

System design can feel overwhelming when concepts are scattered across articles, videos, and interview guides. This textbook brings them together into one structured learning resource.

**System Design: From First Principles to Production** is a free, 305-page textbook for students, beginners, and working engineers who want to understand not just *what* system design concepts are, but *why* they matter and *when* to use them.

Start with the fundamentals, learn how networks and databases work, explore scaling and reliability, and apply your knowledge to practical system design problems.

### ✨ What makes this textbook useful?

- 📚 **Structured learning:** Progress from core concepts to complete system designs.
- 🧠 **First-principles explanations:** Build an understanding of the reasoning behind architectural decisions.
- 🔢 **Worked examples:** Practice capacity estimation and numerical reasoning with stated assumptions.
- 🗺️ **Diagrams and architecture walkthroughs:** Understand how system components interact.
- 💼 **Interview preparation:** Explore system design questions, answers, and practical design approaches.
- 🛠️ **Object-oriented design:** Study design problems with code examples and tests.
- 📝 **Practice with answers:** Reinforce learning through exercises and revision checklists.

> The goal is to help you develop system design judgment, not simply memorize architecture diagrams.

## 📚 Explore the Contents

The textbook is organized into nine parts, followed by appendices.

| Part | Topics covered |
|---|---|
| **I. Foundations** | System design fundamentals, concurrency, data structures, estimation, and capacity planning |
| **II. Networking and the Entry Layer** | Networking, request lifecycle, REST, RPC, CDNs, load balancers, and proxies |
| **III. Data** | Relational databases, SQL scaling, NoSQL, consistency, availability, and partitioning |
| **IV. Performance and Asynchrony** | Caching, queues, pub/sub, outbox patterns, and sagas |
| **V. Reliability** | Time, coordination, consensus, resilience patterns, and microservices |
| **VI. Security and Operations** | Security, privacy, observability, SLOs, disaster recovery, deployment, cost, and capacity |
| **VII. Interviews and Worked Systems** | Pastebin, Twitter timeline, web crawler, Mint, social graph, query cache, sales rank, payments, notifications, and scaling to millions |
| **VIII. Object-Oriented Design** | Hash map, LRU cache, call center, cards and blackjack, parking lot, chat, and circular buffer |
| **IX. Practice** | 23 additional design questions with starting sketches and real-world architecture reading |
| **Appendices** | Revision sheets, formulas, coverage matrix, glossary, references, and index |

### 🧩 A consistent learning format

Each chapter includes learning objectives, key terms, worked examples, failure modes, common misconceptions, interview Q&A, exercises with answers, a summary, and a revision checklist.

The object-oriented design section also includes code examples described as tested in the repository.

## ✅ Quality, Accuracy, and Transparency

This project aims to provide a useful learning resource while being transparent about its limitations.

- **Document checks:** The quality report describes checks for page sizes, fonts, links, bookmarks, contents-page numbering, and margins.
- **Visual review:** The report describes a visual review of the pages.
- **Practice assumptions:** Capacity-estimation figures are illustrative assumptions for learning, not production benchmarks.
- **References:** The content was written from the author's knowledge. External references have not been independently re-verified online.
- **Corrections:** If you discover an error, unclear explanation, or broken reference, please open an issue.

Read the [Quality Assurance Report](docs/QA_REPORT.md) for the documented checks and review process.
